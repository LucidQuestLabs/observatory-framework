# Backlog Questions

See `docs/founding_decisions.md` for current provisional answers and operating defaults. The questions below remain the broader decision backlog.

## Scope and Domain

1. What exact geography should the first MVP target cover?
2. Is the first target a specific company, facility, jurisdiction, or issue cluster?
3. Are we focusing first on water, energy, permits, land ownership, community impact, or all of them?
4. Should the first dossier be public-facing or internal only?
5. Is the first output meant for a coworker, civic partner, client, journalist, attorney, or internal strategy?

## Data Handling

1. What data can be public?
2. What data must remain restricted?
3. Should raw source files be stored in the repo or referenced externally?
4. Should copyrighted articles be summarized only, with links retained?
5. What redaction standards should apply?

## Review Authority

1. Who can approve observations?
2. Who can publish reports?
3. Who can mark material restricted?
4. Who can correct ledger entries?
5. Does any output require legal review?

## Technical Implementation

1. Should the first implementation use GitHub, local folders, Drive, Notion, Airtable, or a custom app?
2. Should JSONL be the first ledger format?
3. Should validation scripts run immediately?
4. Should agents submit pull requests or plain review packets?
5. Should source snapshots be archived locally?

## Product

1. Which parts are open-source?
2. Which parts become paid consulting deliverables?
3. Which datasets become productized?
4. What are the first three paid offerings?
5. What level of transparency should be used with clients and public audiences?

## Risk and Ethics

1. What claims require legal review before publication?
2. How should community testimony be handled?
3. How should anonymous sources be treated?
4. What is the escalation path for serious allegations?
5. What is the correction policy after publication?
